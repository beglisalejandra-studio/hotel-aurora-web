# Módulo: i18n (multiidioma)

| Ficha | |
|---|---|
| **Objetivo** | Servir el sitio en varios idiomas con SEO correcto (hreflang, canonical, sitemap por idioma). |
| **Datos** | Preferencia de idioma (Accept-Language, no se almacena). |
| **Cliente / servidor** | Negociación y rutas en servidor; textos en diccionarios fuera de los componentes. |
| **Credenciales** | Ninguna (servicios de traducción/CMS aparte, con su ficha). |
| **Coste** | 0 en código; el coste real es la traducción y revisión humana del contenido. |
| **Privacidad** | No se guarda el idioma en cookie salvo que el usuario lo elija explícitamente (cookie de preferencia, declarada en el mapa de datos). |
| **Fallback** | Idioma por defecto si falta una clave/traducción. |
| **Pruebas** | `tests/unit/i18n.test.ts` (negociación, hreflang, forma de diccionarios). Añade e2e: cada idioma responde 200, `lang` correcto en `<html>`, `hreflang` recíproco. |
| **Responsable** | (definir en PROJECT.md) |

## Qué aporta este módulo (verificado por tests)
`lib/i18n/config.ts` (idiomas, `negotiateLocale`), `alternates.ts` (`alternatesFor` → canonical + hreflang + x-default), `dictionaries.ts` (diccionarios tipados).

## Qué NO hace (PR dedicado — sigue la guía oficial de Next: https://nextjs.org/docs/app/guides/internationalization)
1. Mover las rutas bajo `app/[lang]/` y validar `lang` con `isLocale` (404 si no).
2. `proxy.ts`: redirigir `/` → `/<idioma negociado>` (`negotiateLocale`) sin romper los bots (respeta `x-default`).
3. `<html lang={lang}>` dinámico (sustituye el `lang` fijo de `app/layout.tsx`).
4. `generateMetadata` con `alternates: alternatesFor(path, lang, site.url)` en CADA página.
5. `app/sitemap.ts` (vía `lib/sitemap-sources.ts`): una entrada por idioma con `alternates.languages`.
6. Contenido: textos fuera del código; fechas, moneda y plurales localizados (`Intl`); **sin traducción automática sin revisión humana**.
7. Actualiza `docs/privacy/data-map.md` y las pruebas e2e.
